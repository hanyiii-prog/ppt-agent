# V2.2 Plan: Page-Kind DNA + Element Cache + Component Store

## Requirements

1. Per-page-kind DNA: cover/toc/section/content/closing/special each get their own shape/layout/typography/color segments extracted from that kind's slides only. Generation reads the matching kind's DNA.
2. Template isolation: every template carries a SHA-256 fingerprint; mixing payloads from different templates is refused at the pipeline entry.
3. Persistent component store (cross-project): structure + relative geometry stored; colours/fonts/transparency resolved from the active template's page-kind DNA at render time.
4. Token-efficient element store: fingerprint-cached element templates; cache hits cost zero tokens; misses generated (rules first, LLM as bounded fallback) and stored for future reuse.
5. Fix all V2.1 review findings (component matcher wiring, design rules wiring, post-render repair, rasterizer detection, theme integration, configurable layout engine, spacing graph optimisation, README, CI).
